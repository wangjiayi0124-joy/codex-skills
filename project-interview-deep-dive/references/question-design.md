# 问题与深挖规则

## 从真实面试路径设计问题

先找“面试官为什么会继续问”，再确定问题。常见起点包括：项目总述、本人做了什么、为何做这个功能、MVP 如何收敛、最大挑战、效果如何、复盘如何改进。

将项目中的真实矛盾转为独立问题，而不是把它们塞进同一题。示例逻辑：

- 有方案前后变化：问“为什么从初始方案改成最终方案？”
- 有角色利益冲突：问“为什么这样做不会伤害合作方/另一角色？”
- 有不确定效果：问“你如何灰度/验证，而不是直接全面推开？”
- 有跨部门依赖：问“最大挑战是什么？你如何明确负责人、边界和交付？”
- 有 AI 能力：问“Agent 的边界、触发、人工兜底和效果怎么设计？”

## 使用四类深挖视角，但不要机械套用

以下四类是发现问题的视角，不是每道题都要遵循的答题框架：

1. **判断逻辑**：为什么这样选？是否考虑公司战略、业务指标、用户需求、成本、周期、生态约束或风险？
2. **行动过程**：不是只列措施；说明初始方案、替代方案、调研发现、核心链路优化和最后的取舍。
3. **可迁移能力**：协助工作也可拆出对齐需求、整理复杂信息、推进反馈、发现流程漏洞、把模糊问题变成行动。
4. **真实拉扯**：资源不足、周期紧、跨部门难推、方案上线后数据一般、合作方冲突等。说清限制与处理，比只报好结果更可信。

## 选择回答结构

- **按维度**：只有不同角色或利益点真的不同，例如客户、合作方、平台、实现成本。
- **按时间**：适合协同推进、问题解决和方案演变。
- **按因果**：适合决策、MVP 取舍和指标设计。

不要把一句本可合并的因果关系拆成两条平级内容；也不要为了整齐把“挑战”与“价值”放在同一层。

## 思考与升华的证据边界

- 从项目中的选择、数据、反馈、限制和复盘提炼，不从空泛概念出发。
- 区分：**已验证结论**、**当前判断**、**待验证假设**。
- 方法论必须能够回到本项目的具体证据，且表达为可迁移的做法，不夸大为普适规律。

## AI/Agent 的补充提问

根据材料选择，而非全部强行使用：

- 为什么引入 Agent，而不是只优化人工流程？
- Agent 应该优先承接、辅助人工还是兜底？为什么？
- 什么情况下触发？根据什么信息判断？
- 错误回复、误推荐、打扰用户或伤害合作方关系如何防范？
- 如何逐步灰度和衡量效果？灰度不等于 A/B Test；按实际方法表述。
